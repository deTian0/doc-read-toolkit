# 工程化提升计划

> 状态：本轮已落地（待巩固） · 更新日期：2026-11-25
> 范围：工具树融合（`打包/` → `tools/`）+ 文档库迁入 `local/` + 配置/测试

## 1. 背景与目标

当前仓库把三件事揉在根上：

1. **按日/月平铺的文档内容**（`2026-08/`、`2026-11-19/` …）
2. **本机 Claude skill**（`.claude/skills/doc-read`）
3. **另一份可分享工具项目**（`打包/`：doc-read 副本、weread、paid_doc_archiver、README）

结果是根目录嘈杂、双份 skill 漂移、路径硬编码、无测试。

### 本轮目标（已确认）

| # | 目标 | 说明 |
|---|------|------|
| A | **文档进 `local/`** | 不再在仓库根平铺日期目录；采用 `local/YYYY-MM/DD/` 两层 |
| B | **`打包/` 吸收为 `tools/`** | 另一项目融进本库，成为唯一工具子树（可再打包分享） |
| C | **配置 / 密钥外置** | 路径环境变量；密码可外置；分享默认可保留密码 |
| D | **`CLAUDE.md` + 最小 pytest** | 约定与回归 |

### 已确认布局策略

**文档（内容库）**

```text
local/
  2026-08/                 # YYYY-MM（往月：整月一层即可，见下）
    付费文/
    未统计/
  2026-11/                 # YYYY-MM
    19/                    # DD（当月按日）
      付费文/
      未统计/
    25/
      付费文/
      未统计/
```

约定：

- 第一层：`local/YYYY-MM/`
- 第二层（当月/需要按日时）：`DD/`（两位数日，如 `01`、`19`）
- 往月若已按整月归并、不再拆日：允许 `local/YYYY-MM/{付费文,未统计}/`（无 `DD` 层）
- 归档工具默认 `OUTPUT = <仓库根>/local`
- 根目录现有 `2026-*` **迁移进** `local/`（一次性搬迁脚本或 archiver 的 migrate 模式），迁完后根上不再出现日期目录

**工具（原「打包」项目）**

```text
tools/                          # 由 打包/ 吸收融合而来
  README.md
  requirements.txt
  .claude/skills/
    doc-read/
    weread-skills/
  paid_doc_archiver/
  _asr_tools/
```

- `tools/` = 可分享工具包的真相源（取代「根 skill 一份 + 打包一份」）
- 仓库根的 `.claude/skills/` 改为**指向/同步自 `tools/.claude/skills`**（见 §3），避免继续双份手改
- 原目录名 `打包/` 在融合完成后删除或仅短暂保留迁移说明；`打包.zip` 改为从 `tools/` 打出

### 明确不做（本轮）

- 拆分 `extract_docs.py` 为多模块
- 上重 CI / PyPI
- 改文档正文内容（只搬家与改工具默认路径）

## 3. 工作项拆解

### P0-1 · 文档迁入 `local/YYYY-MM/DD`

**搬迁规则（`scripts/migrate_to_local.py`）**

| 现有根目录 | 迁到 |
|------------|------|
| `YYYY-MM-DD/{付费文,未统计,索引,...}` | `local/YYYY-MM/DD/...`（从日期解析月、日） |
| `YYYY-MM/{付费文,未统计,...}` | `local/YYYY-MM/...`（整月，无 DD 层） |
| 根级 `索引/` | `local/索引/` 或按月挂到对应 `local/YYYY-MM/索引/`（实现时选一种写进脚本默认并文档化） |

**归档工具**（`tools/paid_doc_archiver`）

- `DEFAULT_OUTPUT` → `YOUR_DOC_ROOT/local`（或 env `DOC_READ_LOCAL` / `DOC_LOCAL_ROOT`）
- 当月：写入 `local/YYYY-MM/DD/{付费文\|未统计}`
- 往月：写入 `local/YYYY-MM/{付费文\|未统计}`
- `rollup`：把 `local/YYYY-MM/DD` 扁平移入 `local/YYYY-MM`（逻辑与现有类似，换根路径）

**doc-read / SKILL**

- 所有示例路径从 `2026-11-18/付费文` 改为 `local/2026-11/18/付费文`
- 粗读报告默认扫 `local/...`；索引 HTML 建议写在对应月或日目录下的 `索引/`

**验收**

- 根目录不再有 `2026-*` 目录
- 抽样打开迁后路径，文件齐全；归档新跑进入 `local/`

### P0-2 · `打包/` 吸收为 `tools/`

**步骤**

1. 将 `打包/` **重命名/复制**为 `tools/`（保留其 README、requirements、weread、archiver、_asr_tools、skills）
2. 以 **功能更全 / 更新的一侧** 合并 doc-read：
   - 对比根 `.claude/skills/doc-read` 与 `tools/.claude/skills/doc-read`
   - 合并进 `tools/.claude/skills/doc-read`（真相源）
   - 路径改为占位符 + env（本机通过 env 指到 `d:\文档`）
3. 根目录 `.claude/skills/`：
   - **推荐**：`scripts/sync_skills.py` 把 `tools/.claude/skills/*` 同步到根 `.claude/skills/`（Windows 可用复制；有权限再用 directory junction）
   - Claude Code 仍从仓库根加载 skills，但人只改 `tools/` 下副本
4. 删除空的 `tools/scripts/` 壳，或改成放置 `migrate`/`sync` 的说明（真正脚本在仓库根 `scripts/`）
5. 融合稳定后移除旧 `打包/`（或留下仅含「已迁至 tools/」的 README 一回合再删）
6. 分享物：`python scripts/build_share_zip.py` → `tools.zip`（默认保留密码；`--scrub-passwords` 可选）

**验收**

- 日常改 skill 只动 `tools/.claude/skills/...`
- `sync_skills` 后根 `.claude/skills` 一致；`doc-read` / `weread-skills` 在 Claude Code 仍可调用
- 不再维护「打包 vs 根」两套手改流程

### P0-3 · 配置 / 密钥外置

| 变量 | 用途 |
|------|------|
| `DOC_READ_ROOT` | 仓库/文档库根（默认仓库根） |
| `DOC_LOCAL_ROOT` | 内容库根（默认 `$DOC_READ_ROOT/local`） |
| `DOC_READ_PYTHON` | conda/venv python |
| `WECHAT_MSG_FILE` | 微信 `msg\file` |
| `WEREAD_API_KEY` | 已有 |
| `DOC_READ_PASSWORDS` | 可选，逗号分隔额外密码 |

- `secrets.local.json`：`{ "passwords": [...] }`（gitignore）
- `extract_docs.py`：密码 = 内置默认 ∪ secrets ∪ env；CUDA 路径基于 env 前缀
- `.cmd`：优先 `DOC_READ_PYTHON`
- 分享默认真相源内可保留常用密码；`build_share_zip --scrub-passwords` 对外

### P0-4 · `CLAUDE.md` + 最小测试

**`CLAUDE.md` 要点**

- 内容在 `local/YYYY-MM/DD`；工具在 `tools/`
- 只改 `tools/` 下 skills，改完跑 `sync_skills`
- 密钥与 env 约定；常见命令（extract / 粗读卡片 / 归档 / migrate）
- 链到本文与 `tools/README.md`

**`tests/`**

- archiver：`classify_category`、冲突改名、`local/YYYY-MM/DD` 路径拼接
- extract：`clean_text`、`is_probably_scan`、`password_candidates`、`paths_for`
- migrate：给定假目录树，断言迁后路径

```bash
python -m pytest tests/ -q
```
